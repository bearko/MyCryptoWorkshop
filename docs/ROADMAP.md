# My Crypto Workshop — 本格開発ロードマップ

MVP（Phase 0）の上に、Bookstore Incremental の機能・イベント・スキルツリーの構成を
マイクリの世界観に置き換えて積み上げていくための計画です。
コンセプトや素材の使い方は [GAME_DESIGN.md](GAME_DESIGN.md) を参照してください。

- **配布形態:** 無料配布（Web / PWA）。
- **目標プレイ時間:** クリアまで 6〜8 時間、クリア後に周回（強くてニューゲーム）。
- **スキルツリー規模の目標:** 現在 50 ノード → 最終 1,000 ノード以上（レベル込みで 3,000 段階以上）。

- 枝の奥ほど、倍率系（×1.5）を少数、加算系（+10%）を多数にする。

## 3. 画面レイアウト方針（店舗の空きスペース）

縦長画面で広がった店舗の床を、段階的に埋めていきます。

```
┌──────────── 工房（変更なし） ────────────┐
│ 壺(1号) / 鍛冶炉(2号) / カプセル(3号) / 分解炉 │
├──────────── 店舗 奥の壁 ─────────────────┤
│ 窓   陳列棚×3(→ショーケース)      入口     │
│ ─ 客の通路 ─────────────────────────────── │
│ [設備スロット 1〜4]  絨毯・ポーション台・試し斬り場 │
│ レジ(クリスくん)＋行列   [スタッフの持ち場 1〜6] │
│ ─ 店外（行商人・マーケット出荷・乗り物の停留所） ─ │
└─────────────────────────────────────────────┘
```

- 設備とスタッフは**決まったスロット**に置く（自由配置はしない）。スロットはシーン高さに応じて並べ直す。
- PC 等の横長画面では床が狭いので、スロットの一部は HUD 下のアイコン表示に切り替える。

| バランス計測 | `npm run balance`（active / casual / idle の 3 モデル、CSV と目標比較表） |

**計測で分かったこと（Phase 2 以降への入力）**

- 現在のコンテンツは約 30 分（active）でツリー全習得に到達。目標の 7 時間には Phase 2〜5 のコンテンツが必要。
- 3 タップ/秒と 1 タップ/秒でほぼ同じ速さで進む＝**タップの価値が低い**。Phase 2 のオーバークロック等で手動操作の価値を上げる。
- 放置（タップなし）でも active の約 1.5 倍の時間で全習得できる。自動化要素を足す前に手動の優位を作る必要がある。

**当初の計画**

目的: 遊びは変えずに、ノードやイベントを数百単位で足せる構造にする。

- `shop.ts` をシステム単位に分割（生産ライン / 陳列 / 客 / レジ / イベント / スタッフ）。
- **スキル効果のデータ駆動化**: `computeStats` の手書き分岐をやめ、ノード定義に `effects: [{ stat, op: 'add' | 'mul', value }]` を持たせる。
- ツリー UI の拡張: ミニマップ、枝ごとのジャンプ、購入可能ノードの一覧、まとめ買い。
- 大きな数の表示（万 / 億 / 兆 / 京）と、セーブデータのバージョン管理・移行。
- スプライトアトラス化（読み込み高速化。プレビューのファイル数上限も解消）。
- 素材同期の全面化（146 シリーズ、全ヒーロー、真・Modern シリーズ）。
- バランス用ツール: シミュレーション結果を CSV に出し、目標の曲線（§5）と比較できるようにする。

**完了条件:** 既存 50 ノードがデータ定義に移行済み。テストが通り、ノードを 1 件足すのにコード変更が要らない。

### Phase 3: 店舗の拡張とスタッフ

目的: 空いた床を使い、アクティブな遊びから自動化への移行を作る。

- 自動レジ、まとめ会計、行商人、マーケット出品（放置収入）。
- 研究ポイントと研究ブランチ。
- ツリー +250 ノード（青龍・黄竜・新ブランチ「店舗」）。

**完了条件:** 手を離しても営業が回る。スタッフを雇うと画面上で働く姿が見える。

### Phase 4: 客層とイベント

目的: 毎日の営業に変化と判断を入れる。

- 新しい客層: 属性・勢力別の客、コレクター客（図鑑にない品を高く買う）、ギルド団体、ランドオーナー。
- 乗り物（乗合馬車 / 飛空艇 / ランドゲート）による団体客の波。
- 店内イベント（§2.5）: 店舗エネミー、宝箱の飛来と散らかり、天候（雨 / 霧）、悪徳商人（選択式）。
- お助けキャラの来店（MAI、クリプタイド）、泥棒の改心。
- 高レア完成時の金宝箱演出とカットイン演出（素材リポジトリの既存 CSS / JS を利用）。
- ツリー +200 ノード（白虎・青龍）。

**完了条件:** 1 日の中で最低 1 回は判断を迫るイベントが起きる。イベントごとに対策ノードかスタッフがある。

### Phase 5: コンテンツの量産

目的: プレイ時間とコレクション欲を伸ばす。

- 全 146 シリーズ（約 950 種）＋ Modern ＋真シリーズ。シリーズ別価格ノード（約 300）。
- ヒーロー図鑑（来店記録）、勢力・属性ごとのコンプリート報酬、常連客と好感度。
- 注文システム（ゆかりの品）。
- 実績とデイリー依頼（エンブレム / ゴールドダスト報酬）。

**完了条件:** ツリー 1,000 ノード以上。クリアまで 6 時間前後（シミュレーション値）。

### Phase 6: エンドゲームと周回

目的: 明確なゴールと、クリア後の遊び。

- **黄金のエクステンション**（5 億 GUM）でクリア演出。
- 強くてニューゲーム = **ランド移転**: クリプタイドの加護（永続ボーナス）を選んで最初から。Cp を周回通貨に。
- 名声（寄付係）、レイド、統計画面。

**完了条件:** 2 周目が 1 周目の半分以下の時間で進む。周回で新しい選択肢が増える。

### Phase 7: 仕上げと配布

- 全体のバランス調整、チュートリアルの作り直し（マインちゃん）。
- 英語対応（素材 DB に英名あり）、PWA（オフライン・ホーム画面追加）、セーブのエクスポート / インポート。
- 低スペックスマホでの性能確認、アクセシビリティ（色覚、効果音オフ時の視覚フィードバック）。
- 配布: Vercel（現状）、itch.io 等。

## 6. リスクと対策

| リスク | 対策 |
| --- | --- |
| ノード数が増えてツリーが見づらくなる | Phase 1 でミニマップ・一覧・検索を先に作る |
| 自動化が進むと触ることがなくなる | 手動の方が強い要素（オーバークロック、イベント、注文）を常に残す |
| スマホで店舗の要素が密集してタップしにくい | 設備・スタッフは固定スロット制、タップ判定は見た目より広く |
| 素材の読み込みが重い | アトラス化、画面外の素材は遅延読み込み |
| バランス崩壊（倍率の掛け算で爆発） | 倍率系ノードを絞り、シミュレーションを毎フェーズ回す |
